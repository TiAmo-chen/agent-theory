## 0. 贯穿全阶段的思维模型

```
你的代码 → openai SDK → HTTP POST → 模型服务端(DeepSeek) → JSON 响应 → SDK 解析 → Python 对象
```

**一句话定生死**：
- **字段名**（`choices` / `finish_reason` / `tool_calls` / `usage`...）是 **openai-python SDK 定义**的
- **字段值**（`"stop"` / `"tool_calls"`...）是 **模型服务端决定**的
- 你代码里 `finish_reason == "tool_calls"` 是拿服务端返回值去比较枚举，不是自创

## 1. 消息结构（1.1）：三种 role

| role | 作用 |
|------|------|
| `system` | 设定角色/行为规则，不被用户覆盖 |
| `user` | 用户的问题/指令 |
| `assistant` | AI 的回复（多轮对话时把上一轮答案追加回 messages） |

**多轮记忆的本质** = 把历史 `assistant` / `user` 消息**逐条追加**进 `messages` 数组，再发一次。
模型本身无状态，`messages` 就是它唯一的"记忆载体"。

```python
messages = [{"role": "system", "content": "你是编程助手，回答简洁"}]
messages.append({"role": "user", "content": "list 和 tuple 的区别？"})
resp = client.chat.completions.create(model=MODEL, messages=messages)
messages.append({"role": "assistant", "content": resp.choices[0].message.content})
# 下一轮就有了"记忆"
```

## 2. Request / Response（1.1b）：模型能接受什么、返回什么

### 能【接受】（create 的常见参数）
`model`(必) / `messages`(必) / `tools` / `tool_choice` / `response_format` /
`temperature` / `top_p` / `max_tokens` / `stop` / `stream` / `n` / `seed` / `user`

### 能【返回】（ChatCompletion 对象骨架）
```
id · model · created · object · choices[] · usage
choices[0]
  ├─ finish_reason   # "stop"|"length"|"tool_calls"|"content_filter"|"function_call"
  └─ message
      ├─ role        # "assistant"
      ├─ content     # 文本（调工具时常为空串）
      ├─ tool_calls[]# ★ 模型想调的工具
      │    └─ id / type:"function" / function{ name, arguments(JSON字符串) }
      └─ refusal
usage: prompt_tokens / completion_tokens / total_tokens
```

### finish_reason 五值
| 值 | 含义 |
|----|------|
| `stop` | 模型说完了（直接回答） |
| `tool_calls` | ★ 模型决定要调工具 |
| `length` | 超 max_tokens 被截断 |
| `content_filter` | 输出被内容过滤拦了 |
| `function_call` | 旧字段，已废弃 |

## 3. SDK 全貌（1.1c）：别只盯着 chat.completions

SDK = **客户端(发请求) + 资源(每类能力) + 类型(响应对象) + 异常(错误分类)**。

- **客户端** `OpenAI(...)`：可配 `api_key`/`base_url`/`timeout`/`max_retries`/`default_headers`...
- **资源**：`chat` / `embeddings` / `files` / `images` / `audio` / `moderations` / `vector_stores`...
- **类型**：集中在 `openai.types`（如 `types/chat/` 下的 `ChatCompletion`、`ChatCompletionMessage`）
- **异常**：`RateLimitError`(429) / `AuthenticationError`(401) / `APITimeoutError` / `APIConnectionError`...
- 详细：`notes/openai_sdk_全景.md`；跑 `1.1c_sdk_explorer.py` 能看本地真实全貌

**参数三态（易踩坑）**：`NotGiven`(没传→用服务端默认) / `Omit`(显式省略) / `None`(传了 null)。
想要"服务端默认"就**别写**该参数，别写 `=None`。

## 4. 工具调用：Agent 的起点（1.3）

一句话：**`tools` 只是"说明书"，真正执行工具的是你的代码，不是模型、也不是 SDK。**

流程（单轮版）：
```
定义工具 schema（name/description/parameters）
    → create(messages, tools=TOOLS)
    → 模型返回 finish_reason==""tool_calls"" + tool_calls[]
    → 你的代码逐个执行（json.loads(arguments)）
    → 把结果回填 messages（role="tool"，带 tool_call_id）
    → 再调一次模型 → 得到最终文字答案
```

```python
TOOLS = [{"type":"function","function":{
    "name":"get_weather",
    "description":"查询城市温度。当用户问天气时调用。",
    "parameters":{"type":"object","properties":{
        "city":{"type":"string","description":"城市名"}},"required":["city"]}}}]

resp = client.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS)
if resp.choices[0].finish_reason == "tool_calls":
    for tc in resp.choices[0].message.tool_calls:
        args = json.loads(tc.function.arguments)          # arguments 是 JSON 字符串
        result = TOOL_MAP[tc.function.name](**args)       # 你的代码执行
        messages.append({"role":"tool","tool_call_id":tc.id,"content":json.dumps(result)})
    resp = client.chat.completions.create(model=MODEL, messages=messages)  # 结尾这次回答
```

**要点**：description 写清"什么时候用"，模型才选得准；`tool_calls` 是**数组**，可并行调多个工具。

## 5. 常见坑 & 踩坑记录

| 坑 | 现象/后果 | 解决 |
|----|----------|------|
| Windows 控制台 GBK | 打印中文/emoji 报 UnicodeEncodeError | 开头 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` |
| assistant 工具调用消息的 content | 常为 `None` 或空串，`get("content")` 返回 None | 用 `(m.get("content") or "")` 兜底 |
| `tool_calls.function.arguments` | 是 **JSON 字符串**，直接用会错 | 先 `json.loads` |
| 回填 tool 结果 | 不带 `tool_call_id` 会报错/无法配对 | 必须带上 `tc.id` |
| 想用服务端默认参数 | 传 `temperature=None` 会发 null | 别写该参数（三态） |
| DeepSeek 扩展字段 | 返回 `reasoning_content`、缓存统计等 | SDK 宽容存放，代码只依赖标准字段 |
| `finish_reason` 未覆盖 | 出现非预期值时静默失败 | `else` 分支兜底，别只判 stop/tool_calls |

## 6. 通向第二阶段

第一阶段只会**调一次工具**。但它暴露了关键事实：
> 模型第一次只给"我要调 get_weather"的**意图**，结果还没拿到；必须**亲手执行 + 结果回填 + 再调一次**，才有最终答案。

把这段"执行→回填→再调"放进一个 **while 循环**，就是第二阶段的 **ReAct**（Reason→Act→Observe→Repeat）。
再往下就是护栏（MAX_STEPS、错误回填、上下文裁剪）与工具系统（读写文件、跑命令、MCP）。
详见 `notes/react-loop.md`。
